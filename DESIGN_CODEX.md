# 太极 Code 界面设计规范 (Codex 风格)

> 模仿 OpenAI Codex CLI 的极简终端界面风格

---

## 1. Codex 界面特征分析

### 1.1 视觉特点

- **极简主义** — 大量留白，去除冗余装饰
- **单色为主** — 主要使用黑/白/灰，强调色克制
- **清晰层次** — 通过间距和字重区分信息层级
- **紧凑布局** — 信息密度高但不拥挤

### 1.2 核心元素

```
┌─────────────────────────────────────────────────────────────┐
│  codex                                                      │  ← 简洁头部
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  user> 帮我重构这个函数                                      │  ← 用户输入
│                                                             │
│  assistant>                                                 │  ← 助手响应
│  好的，我来分析代码结构...                                   │
│                                                             │
│  [tool: read_file]                                          │  ← 工具调用
│  main.go: 328 lines                                         │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│  gpt-4o  •  3 turns  •  2.4k tokens                         │  ← 状态栏
└─────────────────────────────────────────────────────────────┘
```

│    328 lines total                                          │
│                                                             │
│  assistant>                                                 │
│  发现 3 个可以改进的地方：                                   │
│  1. 错误处理不统一                                           │

│  3. 代码重复                                                 │

```

### 2.2 关键变化

| 元素 | 旧设计 (Claude Code 风格) | 新设计 (Codex 风格) |
|------|--------------------------|---------------------|
| 头部 | `太极 Code v0.3.0` | `太极 code` (小写) |
| 用户前缀 | `> ` (蓝色) | `user> ` (灰色) |
| 助手前缀 | 左侧橙色竖线 `│` | `assistant> ` (灰色) |
| 工具调用 | `⎿ tool_name args` | `⎿ tool_name(args)` |
| 工具结果 | 缩进 + `↪` | 直接显示，无图标 |
| 状态栏 | 左侧模式标签 | 右侧模型 + 轮次 + tokens |
| 输入提示 | `> ` (蓝色粗体) | `> ` (灰色) |

```

│  颜色名称        ANSI    用途                                │

│  边框/分隔       238     分隔线                              │
│  用户标签        249     "user>" 前缀                        │
│  助手标签        249     "assistant>" 前缀                   │

- **统一前缀样式** — user>/assistant> 使用相同灰色

## 4. 组件详细设计

### 4.1 头部

```
太极 code
```

**规范**：
- 文字：`太极 code` (小写 "code")
- 样式：粗体，默认文字色
- 高度：1 行
- 无版本号、无模型信息

### 4.2 用户消息

```
user> 帮我重构这个函数
```

**规范**：
- 前缀：`user> ` (灰色 249)
- 内容：默认文字色
- 无缩进、无额外装饰

### 4.3 助手消息

```
assistant>
我来分析代码结构。发现以下几个问题：

1. 错误处理不统一
2. 变量命名不够清晰
```

**规范**：
- 前缀：`assistant>` (灰色 249，单独一行)
- 内容：默认文字色，Markdown 渲染
- 无前缀竖线、无边框

### 4.4 工具调用

```
⎿ read_file(main.go:1-100)
```

**规范**：
- 图标：`⎿ ` (灰色 249)
- 格式：`tool_name(args)`
- 参数：括号内，简洁显示
- 无参数时：` tool_name()`

### 4.5 工具结果

```
  328 lines total
  package main
  
  import (
      "fmt"
  )
```

**规范**：
- 缩进：2 空格
- 无图标、无前缀
- 代码块：等宽字体，语法高亮
- 最大高度：15 行 (可展开)

### 4.6 权限请求

```
⚠ Permission required: write_file(main.go)

Allow? [y/n/a]
```

**规范**：
- 图标：`⚠ ` (黄色 220)
- 文字：黄色
- 输入：单字符 (y/n/a)

### 4.7 状态栏

```
deepseek-chat  •  3 turns  •  2.4k tokens  •  [auto]
```

**规范**：
- 位置：底部，分隔线上方
- 分隔符：` • ` (灰色 245)
- 内容：模型名 + 轮次 + tokens + 模式
- 样式：灰色 245，斜体

### 4.8 输入区

```
  > _
```

**规范**：
- 前缀：`> ` (灰色 249)
- 光标：反向块光标
- 位置：最底部

## 6. 实现要点

### 6.1 需要修改的文件

| 文件 | 修改内容 |
|------|----------|
| `internal/ui/tui.go` | 颜色方案、渲染函数、布局逻辑 |
| `internal/ui/markdown.go` | Markdown 渲染样式 |

### 6.2 核心变更

1. **颜色变量重定义**
   ```go
   // 旧
   claudeOrange = lipgloss.Color("204")
   userBlue = lipgloss.Color("75")
   
   // 新
   primaryText = lipgloss.Color("15")
   secondaryText = lipgloss.Color("245")
   prefixGray = lipgloss.Color("249")
   ```

2. **渲染函数重写**
   - `renderUserBlock`: 改为 `user> ` 前缀
   - `renderAssistantBlock`: 改为 `assistant>` 前缀 + 内容
   - `renderToolCallBlock`: 改为 ` tool(args)` 格式
   - `renderToolResultBlock`: 去除 `↪` 图标，改为缩进

3. **状态栏重设计**
   - 显示模型名、轮次、tokens、模式
   - 使用 ` • ` 分隔
